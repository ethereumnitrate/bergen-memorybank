# Bergen Memory Bank Ten-Minute Presentation Script

Use the synthetic course and examples below. Do not substitute real student information during the presentation.

## [0:00–1:00] Faculty value

**Say:** “Bergen Memory Bank is a faculty-controlled planning and reflection partner. Its faculty value is continuity: it helps keep a course outcome, introduced concepts, active drafts, decisions, and reusable practices visible while the faculty member remains in control.”

**Show:** The classic custom Gem and the four document roles: shared Faculty Profile; shared Decisions, Reflections, and Reusable Practices; course-specific Course Memory; and course-specific Active Workbench.

## [1:00–2:15] Privacy first

**Say:** “Canvas is the student-record system. This demonstration uses synthetic safe examples only. We do not paste student submissions, identifiers, individual grades, student-specific feedback, protected details, or identifiable quotations.”

**Show:** The blank de-identified Class Learning Snapshot. Explain that protected content triggers an immediate stop without echoing or transforming it, and that work resumes only from a newly supplied safe snapshot.

## [2:15–3:15] Start and resume verified course memory

**Type:** `bergen:init COM-101: Public Speaking Fundamentals`

**Say:** “Google Keep is the active memory inside Gemini. Initialization may create only a low-risk temporary checkpoint automatically. A successful write requires creation, retrieval of the exact new Keep note, comparison with the intended content, and then the success report. If any step fails, the proposed content and failure stay visible in Gemini.”

**Show:** In a new safe chat, use `bergen:resume COM-101` and then `bergen:memory`. Point out the exact Keep note titles used, conflicts or missing information, the last verified write, the current stage, and the next command.

## [3:15–4:30] Commands and ordinary language

**Say:** “The seventeen commands are optional prompt conventions: help, setup, init, resume, memory, course, lesson, assignment, rubric, reinforce, review, revise, message, reflect, record, package course, and package assessment. Ordinary language follows the same safeguards.”

**Type:** `bergen:lesson Plan a brief lesson on a clear central claim and relevant evidence.`

**Then type in a fresh safe example:** “Review this synthetic lesson without changing it.”

**Show:** Matching workflow headers and the minimum-question rule.

## [4:30–6:30] Aligned draft, review, and approval

**Say:** “The synthetic journey holds one outcome steady from lesson to assignment to rubric. Review reports alignment, clarity, accessibility, cognitive load, quality, prerequisite creep, and bias. It does not silently revise.”

**Show:** A lesson using concepts already introduced; an assignment requiring a central claim and two relevant evidence points; and a rubric covering central claim, evidence relevance, audience adaptation, and organization.

**Say:** “Revision waits for explicit faculty approval. Recording waits for separate approval. Publication waits for another separate approval and faculty action.”

## [6:30–7:30] Context estimate

**Say:** “A context percentage, when defensible, is only a low-confidence conservative visible-chat estimate. The 32,000-token Education Fundamentals denominator is unverified. It is not actual remaining capacity and excludes hidden, system, and Gem instructions, retrieved knowledge, and actual model capacity.”

**Show:** Rounded guidance: below about 50% may continue; about 50–70% should record soon; above about 70% should record and start a new chat. Restart earlier when courses mix or decisions are lost. Hallucinations can occur at any percentage.

## [7:30–9:00] Manual Canvas, whole-course package, and optional QTI

**Type:** `bergen:package course`

**Say:** “After separate whole-course approval, Gemini prepares one Bergen Course Transfer Block. The browser-only Bergen Course Packager validates it and creates one whole course as a local `.imscc`. The faculty member manually imports it into an unpublished Canvas sandbox, waits for the import job to complete, reviews Modules, and decides separately whether to publish. Bergen Memory Bank does not publish.”

**Type:** `bergen:package assessment`

**Say:** “For an approved synthetic quiz or exam, the separate assessment-only QTI path creates a local ZIP from a Bergen Quiz Transfer Block; it does not create or require a whole-course `.imscc`. The institution-provided packager link is not currently available, so use manual Canvas entry. Use with Bergen Canvas has not been approved.”

**Show:** The distinct manual Canvas import paths and the five supported QTI item types: multiple choice, true/false, multiple answer, short answer, and essay.

## [9:00–10:00] Close and verify

**Say:** “The practical sequence is initialize or resume verified Keep memory, frame one course, plan, draft, review, approve revision, approve a durable record, and complete the local package and manual Canvas actions. The faculty member controls every consequential step.”

**Show:** `bergen:record` as a displayed proposal requiring separate approval and exact-note verification, not an automatic durable save. End with `bergen:help` and point to the privacy checklist, quick start, Keep guidance, course handoff guidance, troubleshooting guidance, and QTI handoff guide.

**Close:** “Bergen Memory Bank adds organized continuity without moving student records out of Canvas or replacing faculty judgment.”
